# C01 authoring-service evidence — 2026-10-27

C01 implements the [service/proposal contract](../chat-authoring-service.md), not the complete chat UI. C02 attachment handling, C03 review/binding/Apply and C04 history remain separate work.

## Local evidence

Typecheck and 405 TypeScript tests across 31 files pass locally. Twenty-one authoring cases exercise all six authoring-capable provider protocols, including Anthropic's response-only JSON schema transport, without offering execution tools. Coverage includes complete candidates/clarifications, app-owned metadata, retained graph IDs/positions/owned values, unsaved draft stamps, explicit deletions, child isolation, binding receipts without invented resources, credential projection/restoration, invalid/unknown/unsafe output, graph/reference/branch/child errors, node/edge/context/depth/response bounds, real deadline cancellation, duplicate Send IDs, request/session isolation, supersession, stale dependencies, unrelated changes and redacted provider failures.

Full renderer acceptance passes, including existing graph/reference/recording/connection journeys. Production build and Xvfb source Electron smoke exercise the actual preload/main/SQLite boundary and production Ollama adapter against private loopback HTTP. Generation returns app-owned unsaved candidates and clarifications, rejects invalid metadata, deduplicates Send IDs, emits scoped progress, cancels a held HTTP request and discards an in-flight result after the saved source revision changes. Saved flows, schedules, targets and runs are compared before/after generation and remain unchanged; only an explicit test save changes the source revision. No provider credential or paid/live inference is used.

The normal three-platform hosted matrix runs that same application journey, existing renderer/native regressions and source/packaged smoke. Final hosted results and artifacts are linked in the PR.

## Limits and remaining acceptance

Protocol fixtures and deterministic model responses do not prove live model quality, image grounding, real provider policy or user-facing chat acceptance. C02 must supply trusted normalized attachments; C03 must implement the review UI, actual resource binding, fresh-preview checks, revision/trigger-aware Apply and duplicate-Apply handling; C04 must implement durable history/retention/restart behavior. C01 writes no proposal/session data and exposes no Apply or Run authority to a model. Native/installer/live-provider qualification gaps in the broader roadmap remain open.
