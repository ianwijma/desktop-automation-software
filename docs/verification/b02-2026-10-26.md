## Acceptance evidence

- [Real browser fixtures](../../tests/browser-locators.test.ts) run against managed Chromium and a loaded extension with the authenticated bridge. The [page fixture](../../tests/fixtures/browser-recording.html) covers replacement typing, actual clipboard paste of synthetic text, textarea/contenteditable, trusted CDP IME input, checkbox/radio state, multiple select, double/right/middle/modifier clicks, paired shortcut keys, wheel scrolling, and a regular pointer drag. Both modes produce equivalent normalized action sequences and replay to the same final field/control/counter/scroll/drag state. Double-clicks and checkbox/select change handling do not add duplicate activations; desired checked-state replay is idempotent and rejects an application-vetoed change without repeating input.
- The same fixtures cover root navigation, History API changes, popup creation, explicit interaction in parent/child tabs, and active popup closure. Pending text precedes each transition. Replay closes the popup and retains the return tab. Exact owner-based frame/shadow fixtures and legacy selectors remain enabled from B01.
- Stop tests cover an unblurred last edit, unfinished held-key release, interrupted composition, omitted password/file values, and a simulated lost Stop response. Retry returns the same action IDs, then a completed second Stop returns no additional actions. Existing browser tests retain session-token, delayed-install, cleanup-failure, and simulated extension worker-memory-loss coverage.
- [Recording controller tests](../../tests/recording-controller.test.ts) prove accepted events precede the Stop tail, late/obsolete callbacks remain rejected, and flushed text survives a release failure and cleanup retry without duplication. [Schema tests](../../tests/browser-locator-schema.test.ts) validate new states, arrays, offsets, destination locators, and manual-configuration blocking.
- [Renderer acceptance](../../scripts/browser-locator-smoke.mjs) uses a controlled desktop API with the production DOM matcher. An omitted password is visibly blocked, acknowledgement is disabled until text is configured, and saving the acknowledged step never changes the separate target page's input/focus. Existing review/edit/undo/insertion acceptance remains enabled.
- [Electron acceptance](../../scripts/smoke.mjs) uses the real preload/main/utility/SQLite boundary and a synthetic browser editing fixture. Browser editing commands produce actual editing events; there is no mocked recording adapter. Unblurred text is saved on Pause, a resumed edit is saved on Stop, and bootstrap returns the acknowledged draft. This supplements the direct-interaction record/replay fixtures; it does not establish native IME or file-dialog support.

## Compatibility and remaining limits

Workflow/database versions remain 2 and recording envelopes remain version 1. Tab is added to the recordable action allowlist. Browser-only optional configuration adds checked state, modifiers, multi-select arrays, absolute scroll positions, drag destination locators/offsets, observed-navigation behavior, exact tab selection/closure evidence, and explicit configuration warnings. Existing CSS Select result shapes and coordinate workflows remain supported. Native adapters reject browser-specific states rather than silently ignoring them.

The browser event set is shared, while managed and extension lifecycle transports use their respective APIs. Trusted interaction provides a managed-tab activation fallback where headless focus reports every page as focused. Transports serialize delivery and keep stable Stop receipts; input is never retried to hide a failed assertion or detached tab. A tab closing during its own mouse release may complete without a debugger reply; only that release acknowledgement is accepted when the tab is confirmed gone.

The IME evidence uses Chromium protocol-driven composition, not real OS input methods. Browser chrome, unrelated tabs, native dialogs, closed shadow roots, specialized drag protocols, arbitrary custom widgets, and native platform/installer qualification remain outside this slice. Review the [coverage guide](../browser-recording.md) before relying on unusual application behavior. Native, AI, chat, and distribution work remain on the roadmap.
