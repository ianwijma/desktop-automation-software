# A04 harness evidence — 2026-10-27

The opt-in [conformance harness](../ai-conformance.md) uses production adapters with explicit model/endpoint/operation configurations and request/time/output/response bounds. Both `--run` and `RELAY_AI_LIVE=1` are required. It reads only explicitly named credential variables; it does not inspect or modify Relay's saved connections or keyring.

## Evidence scope

Local typecheck and 384 TypeScript tests across 30 files pass. Twelve new cases include all seven production provider adapters, all five operations on Ollama/LM Studio protocols, malformed/unavailable/oversized responses, missing keys/runtime identity, unsupported operations, global and per-case budgets, deadline/cold-start labels, cancellation including late successes, report privacy and seven deterministic Jev visual cases. These are mocked protocol/outcome assertions, not actual model observations.

The CLI acceptance harness uses private loopback HTTP only. It verifies each opt-in gate independently, missing-key skip/incomplete exit, actual production Ollama requests and metadata, a held HTTP request closing after cancellation, a saved metadata-only report and redirect rejection without following a second request. Its artifact is explicitly labeled `liveProviderQualified: false`. The same fixture acceptance is added to the three-platform CI matrix; hosted results are linked in this PR.

## Qualification still required

No real provider key, local-model server or paid inference is used for this implementation. Every real OpenAI/OpenRouter/Anthropic/Gemini/Jev/Ollama/LM Studio model/version combination remains unverified. Operator-attested runtime/model revisions are not automatically proven by an extra API request. Cold-start state, actual cancellation/billing behavior, live Jev visual accuracy, usage semantics and representative tasks require separate runs and reports. This PR delivers the harness and CI controls, not completion of A04's live qualification or the broader beta roadmap.
