## Acceptance evidence

- [Browser locator tests](../../tests/browser-locators.test.ts) run against managed Chromium and a real loaded extension with its authenticated loopback bridge. They cover test attributes, role/name, associated labels, IDs, CSS, hidden inspection, malformed CSS, missing and ambiguous results, and unchanged input/focus during inspection. Ambiguous click/read/key/type/select operations fail instead of selecting a first match. Unfocusable key targets reject before keys reach another control.
- The same fixtures change CSS classes while preserving a test-attribute match; exercise legacy CSS type/select workflows; type/read through frame and open-shadow scopes; and click in a cross-origin frame. A second cross-origin frame loading the same URL remains untouched, checking owner identity rather than URL-based frame selection. Missing/ambiguous frame owners produce explicit errors.
- Both adapters directly record the same fixture interactions. Normalized action sequences, labels, values, and structured frame/shadow locators are equal. The test replays captured actions, checks omitted password values, and verifies that Stop removes listeners in root, shadow, and frame contexts. Existing [browser tests](../../tests/browser.test.ts) retain recording epoch, delayed-installation, session-token, cleanup-failure, navigated-tab, and simulated worker-memory-loss coverage.
- [Schema tests](../../tests/browser-locator-schema.test.ts) cover descriptor limits, unsupported versions/strategies, invalid test attributes, mutually exclusive targeting, browser requirements, and inactive-field cleanup. Browser-preview tests reject unavailable inspection. Existing workflow/storage tests retain schema/revision/import-export behavior; the descriptor adds no new persistence format.
- [Renderer acceptance](../../scripts/browser-locator-smoke.mjs) uses the production DOM matcher against a separate synthetic target page behind a controlled desktop API. It tests unique/missing/ambiguous results, suggested locators, save/reload, scope editing, stale-response rejection, unresolved references, and preserved future descriptors. Inspection leaves the target's input/focus unchanged. This controlled API establishes UI behavior, not native or IPC behavior.
- [Electron acceptance](../../scripts/smoke.mjs) uses the actual preload/main/utility boundary. Inspection returns a unique semantic match and an ambiguous CSS match without creating a run. A structured frame locator validates, saves to SQLite, then clicks and reads inside the frame through a real workflow run. Existing X11 capture, detection, input, recording recovery, insertion, and engine branch checks remain enabled.

## Compatibility and limits

Workflow/database schema versions remain 2. Existing CSS selectors are not migrated. Structured descriptors have their own version 1 and preserve frame/shadow scope order. Existing CSS Select output shapes remain unchanged; new structured Select actions return arrays in both adapters. Unsupported descriptors remain stored but cannot execute. Test match is read-only with respect to the application DOM/input and never starts a workflow, although establishing the configured browser connection can launch or attach a browser.

Common HTML role/name sources are implemented in one DOM runtime; full Accessible Name specification conformance is not claimed. Open shadow roots and exact owner-based same/cross-origin frames are tested. Closed shadow roots, browser chrome, restricted pages, specialized drag protocols, and native dialogs are outside coverage. Extension frame pointer mapping rejects rotated/mirrored frames. Dynamic page structure can invalidate generated CSS paths; inspection is a point-in-time result.

B02's broader event recording/normalization is still planned. This establishes local Chromium adapter and source Electron behavior; it does not qualify other operating systems, browser release matrices, live providers, or offline installers. Native, AI, chat, and distribution work remain on the roadmap.
