## Acceptance evidence

- [Insertion tests](../../tests/recording-insertion.test.ts) splice an occupied decision branch and preserve its successor. Other edges, existing nodes/configurations/positions, flow interfaces, and recorded JSON types stay unchanged. Added cards avoid existing cards. Coverage includes implicit `next` edges, empty outputs, detector branches, missing branch choice, Finish/orphan sources, competing edges, and changed source/port/edge/successor/revision.
- The same tests use real SQLite to check the complete pre-insertion graph returned for Undo, revision-checked undo/redo saves, and the new-flow Start → Finish undo baseline. A retry after a later edit returns the current flow with a warning and no obsolete undo snapshot. Stale anchors/revisions preserve the draft without writing a graph or receipt. Existing [storage tests](../../tests/recording-storage.test.ts) retain rollback and restart/idempotency coverage.
- [Renderer acceptance](../../scripts/recording-review-smoke.mjs) selects a canvas connection, carries its branch into recording/review, inserts before its successor, and checks the other branch. It navigates away/back, undoes, saves, redoes, saves, and reloads. It also checks new-flow undo, explicit branch choice when only a decision node is selected, and preserved review after a late destination conflict before creating a new-flow copy. Recording UI acceptance uses a controlled desktop API and production graph helpers; it does not establish native input behavior.
- [Electron acceptance](../../scripts/smoke.mjs) uses the actual preload/main/utility/SQLite boundary. It records a non-executing Wait, inserts on a condition's true edge, then explicitly runs both branches through the engine. Only the true run visits the inserted step, and both runs reach their original Finish/output. Insertion creates no run. The test saves Undo and Redo through revision checks, reloads the app UI, and displays the inserted graph. Existing X11 capture, detection, guided input, recording recovery, cleanup, and orchestration checks remain enabled.

## Compatibility and limits

Workflow/database schema versions remain 2 and recording metadata envelopes remain version 1. Optional anchor snapshots and pre/post insertion snapshots extend existing contracts. R01 drafts with free-tail anchors remain readable; old anchors are never silently reinterpreted as occupied edges. Older receipts without undo snapshots remain valid and do not manufacture history.

One insertion is one graph-history entry. Undo/Redo follow the editor's draft-and-save behavior. New-flow Undo leaves the created workflow with Start → Finish. The last insertion history entry survives navigation within the app session only while the saved revision is unchanged; graph history does not survive restart. Concurrent saves still produce revision conflicts.

Bound insertion requires the original workflow revision. Stale/deleted sources preserve the draft for a new workflow. Only reachable outputs with zero or one successor are offered, and Finish has no output. Unrelated graph errors are not repaired automatically; execution still requires ordinary validation.

This establishes local editor/SQLite/engine behavior and preserves isolated X11 regressions. It adds no native backend, broader browser recording, live-provider qualification, or installer support. Those items, chat authoring, and distribution remain on the roadmap.
