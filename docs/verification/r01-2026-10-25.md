## Acceptance evidence

- [Controller tests](../../tests/recording-controller.test.ts) exercise durable acknowledgement before listeners/events, serialized actions, pause during in-flight input, startup cancellation, listener and held-input cleanup failure/retry, stale sessions, late callbacks, explicit paused target changes, and run exclusion. Interrupted input is retained with uncertainty metadata and is never retried automatically. Review edits, failed-save retries, discard, and insertion cannot call input adapters.
- [SQLite tests](../../tests/recording-storage.test.ts) recover capturing, paused, and review drafts into review without graph changes. They cover stale session/revision/destination writes, duplicate acknowledgement, unsupported metadata versions without database rewrite, discard, stale/deleted/occupied insertion destinations, and transaction rollback. Insertion saves the graph, consumes the draft, and writes an idempotent retry receipt together, including across restart.
- [Browser adapter tests](../../tests/browser.test.ts) exercise actual managed-page and extension listener removal, navigation during capture, old-session event rejection, and repeated recording sessions. A temporary extension fixture hook simulates worker memory loss while its isolated-world listener and session storage survive; Stop cleans the original navigated tab even when a decoy tab takes its former URL. This does not establish Chrome worker suspension timing. [Native tests](../../tests/native.test.ts) exercise recorder stop acknowledgement, restart, and failed emergency-release acknowledgement/retry. The Rust helper joins its recorder worker and child-process cleanup before returning Stop.
- [Renderer acceptance](../../scripts/recording-review-smoke.mjs) starts in one workflow, navigates to another, pauses and explicitly switches target, then edits, duplicates, reorders, deletes, undoes, and redoes reviewed steps. Instrumented input/capture counts remain unchanged throughout review. Discard preserves graph nodes/edges; refresh recovers into review without starting capture; explicit insertion creates one connected flow. Failed-save edits remain available for retry.
- [Electron smoke](../../scripts/smoke.mjs) performs real guided click and typing against an X11 fixture, rejects stale/paused/review input attempts, verifies Stop does not mutate graphs or create runs, saves a reviewed edit, closes and relaunches Electron, and inserts the recovered three-step sequence exactly once without execution. Existing capture, detector-click, clipboard, persistence/conflict, theme, and twelve-child batch checks remain in place.

Screenshots are synthetic and stored under ignored `test-results`; the existing CI artifact upload includes them. Ordinary verification makes no paid provider requests.

## Compatibility and limits

Workflow and database schema versions remain 2. Recording uses separate version-1 SQLite metadata envelopes; unsupported future recording metadata fails before writable initialization. The preload API gains explicit session/revision recording methods; browser preview rejects them as unavailable. Existing flows, targets, providers, schedules, and run snapshots retain their formats.

R01 replaces automatic insertion on Stop with explicit review. New-flow insertion is the default. Existing-flow insertion requires an explicitly selected unused ordinary next output captured at recording start, with the same saved flow revision at insertion. Occupied-edge splicing, decision branch selection, existing-successor reconnection, and whole-insertion graph undo remain [R02](../beta-roadmap.md#r02--predictable-graph-insertion).

This report establishes local source-app behavior and isolated X11 input. It does not qualify Windows/macOS/Wayland runtime behavior, actual installers, broader browser event coverage, or live AI providers. Native recording normalization and secure-field coverage remain N08/N09; stronger capture identity and coordinate contracts remain N01. A crash between an application action and its durable acknowledgement can leave an incomplete step, so recovery explicitly asks the user to review before running.
