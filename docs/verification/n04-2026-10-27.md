# N04 implementation evidence — 2026-10-27

N04 replaces per-screenshot Wayland subprocesses with a persistent restricted PipeWire consumer, adds EIS with a fixed transport per grant, and makes source identity, portal loss and cleanup explicit. Native protocol remains 2 with additive source/Wayland diagnostics. See the [backend guide](../wayland-native.md).

## Automated evidence

- TypeScript check and **323 tests across 25 files** pass locally. Six new adapter cases cover explicit capture before input, fractional source transforms/tokens, revocation without implicit chooser reopening, invalid source identity, original-helper cancellation acknowledgement, failed-cleanup barriers and Stop during a pending chooser.
- **20 Linux Rust tests** pass. New tests exercise a private D-Bus service, actual EI/EIS socket messages and a real persistent GStreamer test-source process. The user's portal, compositor and permission database are not used. Managed-session cases also verify selective modifier release and a failed Close blocking every target until acknowledgement succeeds. Portable error mapping checks preserve cancellation/recovery distinctions and redact payloads.
- The private portal cases observe logical geometry separate from pixel size, a 64-bit nonreusable stream serial, restore-token rotation, chooser cancellation/denial cleanup, missing modern identity, session closure and portal-owner loss.
- The EIS case observes mapped pointer coordinates among multiple absolute devices, button/key down/up frames, Unicode text, scrolling and a server round trip. Pausing a used device makes subsequent input fail. A connected socket failure is terminal; no legacy notification path is available in that transport.
- The persistent consumer case observes successive frames from the same process and verifies termination/reaping on drop. EOS invalidates the grant/cached image, and PNG parsing rejects truncated/oversized input. This uses `videotestsrc`, **not a granted PipeWire source**.
- The production application builds and the source Electron smoke passes through preload/main/utility IPC, including SQLite persistence, credential isolation, real engine execution, browser recording and node editing. The Xvfb/X11 native fixture passes all **eight scenarios**, including capture, input, animated graphics, stale geometry and held-input cleanup. These are regression checks, not Wayland permission evidence.
- `npm run test:native:wayland` without `--run` records incomplete/not-run without launching a fixture or opening a chooser.

## Qualification boundary

This host is X11. **Real GNOME and KDE portal consent, PipeWire source capture and application input have not been qualified here.** The opt-in harness is ready for those sessions, but no passing GNOME/KDE result is inferred from wire-contract tests or Linux CI.

The remaining manual matrix includes actual fractional/secondary displays and scale/source changes, permission revocation while idle and held, source closure/hotplug, compositor restart, restoration under the installed identity, and Stop/Pause shortcut delivery. UTF-8 text through `ei_text` and text available in a supplied keymap are distinct from unsupported composition or arbitrary-layout Unicode. Source runs without an installed desktop entry remain separate from installed-app consent.

N04 is **implemented**, with real-compositor/installer qualification still pending. N05 (element picker and Windows UIA) is the next implementation slice; A01 remains independent. Record future real-session results with the [manual report](../manual-test-report.md) before expanding the platform-support claim.
