## Observed behavior

- Launch, attach and focus select the synthetic fixture. Startup is recorded separately from successful capture/input. Capture must contain the known pink fixture marker before coordinate input is attempted; a valid-but-blank PNG is insufficient.
- Native clicks increment the fixture counter exactly once; text matches the synthetic sample; the secure field reports only presence; scrolling and a pointer drag change observed application state. The observation endpoint cannot synthesize input.
- The WebGL region changes in actual native captures, with a progressing animation. This is software graphics evidence, not a hardware-GPU result. The pre-input synthetic capture was visually inspected for the expected controls/marker/surface.
- Resizing rejects the old detector frame. Cancellation interrupts a drag after the fixture observes the button down while Shift is held; cleanup must produce observed key/button release. The helper restart changes instance identity, rejects the old frame, and successfully resumes input.
- A second fully loaded fixture with the same title causes an unbound attach to reject ambiguity; closing the duplicate restores one match. Duplicate labels are present for later semantic targeting work.
- Contract tests reject unnegotiated, missing/future and malformed protocol data before sending desktop input; preserve permission/backend/operation fields; reject inconsistent transforms; scale X and Y independently; and reject a frame after a handle is reused by a different PID. The existing failed-emergency-cleanup test still blocks subsequent input until cleanup is explicitly retried.
- Browser preview continues to expose no native helper or capture/input readiness. No AI calls or new renderer execution controls are involved.

## Compatibility and remaining evidence

Workflow/database versions stay 2 and recording envelopes stay 1. Coordinate workflows and the public message-based rejection API remain supported. Native protocol 1 requires a matching helper; an old helper fails closed with rebuild/reinstall guidance. Runtime handles/PIDs/helper instances do not become saved target locators. Application identity sources remain labels/classes rather than executable fingerprints, and same-process handle recycling is not universally detectable.

N01 is **implemented**, with the real harness verified locally on isolated X11. Hosted checks build/test the contract on Windows/macOS/Linux and add the explicit native harness on Linux; see the PR for current CI evidence. Windows/macOS native capture/input, installed-app permissions, mixed DPI/negative secondary displays, hardware GPU/native toolkit fixtures, permission revocation, real GNOME/KDE sessions and installer tests remain unverified. Wayland harness runs deliberately report not-run without opening a chooser or injecting input. The existing backends are retained; N02/N03/N04 must provide their platform qualification.
