# N03 implementation evidence — 2026-10-27

N03 links a persistent ScreenCaptureKit/public Accessibility bridge into the Rust helper, replacing screenshot subprocesses and title-dependent AppleScript. Native protocol stays 2 with additive macOS permission/identity/display-scale diagnostics. See the [backend guide](../macos-native.md).

## Local evidence (Linux host)

- TypeScript check and **316 tests across 25 files** pass. New coverage checks Retina pixel-to-point mapping and stale frames after a display-scale change.
- **Six portable Rust tests** pass, including macOS permission/session/capture error mapping and bundle identity preservation.
- Production native/application builds and Electron IPC/persistence smoke pass.
- The production-adapter Xvfb harness passes **8/8 desktop scenarios** with software WebGL. This is Linux regression evidence, not macOS native qualification.

## macOS CI and qualification

The macOS job compiles the Objective-C bridge and AppKit/Metal fixture with the Apple SDK, links the single Rust executable, and runs a pure key/chord framework self-test without requesting permissions or sending input. The opt-in four-case native matrix gates actual capture/input on Screen Recording, Accessibility and an active session. Unavailable cases are incomplete, never passing.

Source and unpacked-application smoke checks assert the ScreenCaptureKit backend and macOS diagnostics; the packaged check additionally verifies its helper path is inside `Relay.app/Contents/Resources/native`. This does not qualify granted installed-app permissions or DMG installation.

Real permission-granted AppKit/GPU effects, Retina/secondary/mixed-scale displays, denied/revoked permission recovery, locking, interrupted streams and installed-artifact identity remain explicit acceptance gaps until an actual report records those scenarios. N03 is **implemented**, not fully platform-qualified. N06/N09 AX selectors/direct recording and D01–D03 distribution remain separate work.
